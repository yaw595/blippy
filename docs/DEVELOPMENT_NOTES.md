# quickshare-mac — experiment notes

Our private copy of [NearDrop](https://github.com/grishka/NearDrop) (Unlicense), a macOS menu-bar app that speaks Google Quick Share. Goal: send and receive files between a MacBook and a Pixel 6 Pro with an app on the Mac only. Files save to Downloads. Upstream rejects AI-assisted PRs, so changes stay here.

`.git` is kept from the clone so `git diff` shows our changes against upstream.

## Changes vs upstream
- `MACOSX_DEPLOYMENT_TARGET` 10.15 → 13.0 (Xcode 27 only supports 12.0+).

## Build (unsigned, no Apple account needed)
```bash
xcodebuild -project NearDrop.xcodeproj -scheme NearDrop -configuration Debug \
  -derivedDataPath build CODE_SIGN_IDENTITY="-" CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO build
```
App ends up in `build/Build/Products/Debug/NearDrop.app`. First run: right-click → Open.

- 2026-11-22 — **MTP cable path + hidden-phone handling.** (1) `Helper/blippy-mtp.c`: command-line helper (`detect`, `send [--dest Download] <file>`) speaking MTP over libusb 1.0.29, built universal and statically linked by `scripts/build-mtp.sh` into `Vendor/blippy-mtp` (configure with `ac_cv_func_pipe2=no`, because the macOS 27 SDK declares `pipe2` as 27+ only and the deployment target is 14). Output protocol: `STATUS`, `NAME`, `PROGRESS sent total`, `DONE`, `ERROR CODE text`. Steps: kill `ptpcamera` (macOS's camera daemon holds MTP phones; retries claim 8x), OpenSession, first writable storage via GetStorageIDs/GetStorageInfo (empty = locked → `LOCKED`), find or create top-level `Download`, unique name from its children, SendObjectInfo, SendObject in 256 KB chunks (zero-length packet when the length is a multiple of the packet size), then GetObjectInfo size check. SIGTERM sends the still-image Cancel request. `Cable.swift`: `MTP` wrapper, `Link.fileTransfer`, `canSend`/`readyName`, adb preferred when both work, folders zipped with `NSFileCoordinator .forUploading`. **Not yet tested against a real phone** (the Samsung was unplugged when it was built). (2) `EndpointInfo` now accepts the 17-byte hidden advertisement; `NearbyConnectionManager` tracks hidden services and tells delegates via `hiddenDevicesChanged(count:)` (default no-op in a protocol extension). Send page: hidden count message, QR/Cable/Help buttons, QR sheet opens once per session after 25 s with no phone. Finding: phones advertise as hidden (flag 0x10, no name) unless Quick Share is actively receiving, so Samsung 'Everyone' alone isn't enough.
